# Инструменты и CI

Встроенный скрипт не заменяет полноценный грамматический движок. Он обеспечивает
повторяемые проверки смешения языков, глоссария, длины предложений и защищённых
инвариантов.

## Встроенная проверка

```bash
python3 <skill-root>/scripts/ru_tech_docs.py lint docs/plan.md \
  --profile docs \
  --glossary docs/glossary.json \
  --format json

python3 <skill-root>/scripts/ru_tech_docs.py guard before.md after.md \
  --glossary docs/glossary.json \
  --format json
```

Если глоссарий меняется одновременно с документом, передайте оба состояния:

```bash
python3 <skill-root>/scripts/ru_tech_docs.py guard before.md after.md \
  --before-glossary glossary.before.json \
  --glossary glossary.after.json \
  --format json
```

`--before-glossary` фиксирует набор `do_not_translate`, существовавший до
редактуры: этот набор обязан сохраниться в `after.md`. Новые элементы
послередакционного глоссария не создают инвариант задним числом. Без
`--before-glossary` параметр `--glossary` используется для обоих состояний,
поэтому существующие вызовы CLI совместимы.

Коды:

| Код | Проверка |
|---|---|
| RTD001 | Латинское слово в повествовательном тексте |
| RTD002 | Запрещённый вариант термина |
| RTD003 | Превышена длина предложения для профиля |

`<skill-root>` — каталог, содержащий `SKILL.md`; не считайте, что текущий
рабочий каталог совпадает с ним. `lint` возвращает 1 при находках. `guard`
возвращает 1 при изменении защищённых элементов. Ошибка чтения документа или
глоссария возвращает 2.

Guard распознаёт fenced и indented code, inline code, ссылки, URL, пути,
файлы, dotted/camel/snake и составные идентификаторы с числовым сегментом,
версии, даты, числовые выражения с оператором и единицей, маркеры требований
и термины глоссария. В структурированном техническом токене перенос между
прозой и inline code не меняет инвариант: путь, параметр, идентификатор и
число извлекаются в обоих форматах. Неструктурированный inline code остаётся
буквально защищённым.

Путь должен иметь однозначный синтаксический признак: абсолютный POSIX/Windows
или UNC-префикс, `./`/`../`, не менее трёх относительных сегментов либо
расширение имени файла. Поэтому двусегментная связка `source/destination` —
проза, а `tests/FullSetLifecycle.Tests.ps1` — путь. Обычное слово вроде
`timeout` защищается только разметкой как code или глоссарием. Успешный guard
— механическая проверка, а не доказательство равенства смысла.

Встроенный разборщик покрывает распространённые конструкции Markdown, но не
является полной реализацией CommonMark AST. Для нестандартных вложенных
контейнеров используйте проектный AST-aware checker или помечайте результат как
«ручная проверка». Нулевой код guard необходим, но сам по себе недостаточен.

`lint` исключает `YAML front matter` в начале документа и `Obsidian wikilinks`
из проверки повествовательного текста: это `metadata` и ссылки, а не русская проза.

RTD001 намеренно широк и может давать много кандидатов. Сначала разбирайте
RTD002 и safety-critical разделы; добавляйте допустимые сокращения в
`do_not_translate` только после проверки, а не ради уменьшения счётчика.

## Внешние слои

- [Vale](https://github.com/vale-cli/vale) — основной CI policy-gate для
  дополнительных терминологических и структурных правил.
- [LanguageTool](https://github.com/languagetool-org/languagetool) — русская
  грамматика и пунктуация. Передавайте только извлечённые текстовые узлы
  Markdown; не применяйте предложения автоматически.
- [CSpell](https://github.com/streetsidesoftware/cspell) — опциональная быстрая
  орфография и продуктовый allowlist. Проверьте лицензию выбранного русского
  словаря.
- [LTeX+](https://github.com/ltex-plus/ltex-ls-plus) — интерактивная проверка
  LanguageTool в редакторе.

Не подключайте англоязычные style packs Vale к русскому тексту без проверки:
правила пассивного залога, регистра и пунктуации могут быть неприменимы.
