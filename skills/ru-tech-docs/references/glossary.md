# Проектный глоссарий

Глоссарий хранится в JSON и проходит code review вместе с документацией.
Сначала найдите уже принятый источник терминов: файлы с `glossary` или
`terminology` в имени, конфигурацию Vale/CSpell и ссылки из `AGENTS.md`. Если
источников несколько, уточните, какой из них нормативный. Только при их
отсутствии скопируйте `glossary.example.json`; пример не является проектным
стандартом.

## Схема

```json
{
  "do_not_translate": ["MSSQL", "ONLINE", "RESTORE VERIFYONLY"],
  "terms": [
    {
      "preferred": "полная резервная копия",
      "forbidden": ["full backup", "полный backup"],
      "note": "Для существительного backup в повествовательном тексте."
    }
  ]
}
```

`do_not_translate` содержит точные токены или фразы. Регистр значим. Эти
значения должны сохраняться при редактуре.

Каждый элемент `terms` содержит:

- `preferred` — каноническую форму;
- `forbidden` — формы, которые линтер должен обнаружить;
- `note` — необязательное пояснение для редактора; скрипт его не использует.

## Правила сопровождения

- Не добавляйте термин только ради подавления предупреждения.
- Не сводите к одному термину разные сущности: например, backup set, файл
  `.bak`, дневной набор и точку восстановления.
- Для многозначного английского слова заведите отдельные контекстные записи или
  оставьте его на ручную проверку.
- Не включайте `source`, `stage` или `node` без определения контекста:
  у них часто несколько корректных русских соответствий.
- При изменении канонического термина обновите документацию одним отдельным
  изменением и проверьте весь репозиторий.
- Имена продуктов и протоколов не обязаны переводиться, но обычные английские
  существительные вокруг них должны быть русскими.
